# Private publisher on Yoga

Writing desk: https://yoga-jiaqi.taile0df21.ts.net:8446/write/

The public blog remains on GitHub Pages. The private desk runs on Yoga behind Tailscale Serve. Only the configured owner's Tailscale identity is accepted. It listens on loopback port 8767; Serve supplies HTTPS and verified identity headers on port 8446. Existing Serve routes are preserved, and Funnel remains disabled.

Connect GitHub starts the official GitHub CLI device-login flow. The owner signs into SjaakieChen at github.com/login/device and authorizes GitHub CLI. The credential remains on Yoga in a dedicated, owner-only state directory; no token is sent to the frontend, public repository, browser storage, or draft backups. This uses GitHub CLI's usual OAuth authorization. The publisher itself permits writes only to `_posts/*.md` and `pages/*.md` in `SjaakieChen/personal-blog`, branch main.

Publish validates the document, sends it to Yoga, commits through GitHub's Contents API, and polls the Pages workflow for the resulting commit. Existing documents require the source blob SHA from the current GitHub index. Concurrent edits return a conflict instead of overwriting. An identical retry detects an already-successful write without making a duplicate commit. Duplicate titles within posts or archive entries are rejected after normalizing case, whitespace and Unicode; editing the same file is allowed. Original publication time and later edits continue to come from Git history. The private index reads GitHub directly, so it does not wait for Pages to rebuild.

The public writer's Publish/Open private desk buttons transfer drafts into the private desk through a checked window-to-window message. Both origin and window identity are checked. Repeated imports reuse the existing draft; duplicate titles are prevented in the editor and consolidated during legacy migration. Published snapshots and unpublished edits remain separately accessible in their sidebar groups. Drafts autosave to that browser's localStorage and can be saved/imported as JSON. Tabs on the same origin save under a Web Lock; persistent deletion records prevent stale tabs restoring removed drafts. Conflicting or consolidated older writing is retained in the same draft's `savedVersions` JSON field, rather than creating duplicate drafts. The canonical v3 store is separate from the legacy store so older tabs cannot overwrite it. Private drafts are synced to Yoga as described below; the public writing page retains browser-local storage.

## Operations

- Source deployment: `/home/jiaqi/.local/share/blog-publisher`.
- Private state: `/home/jiaqi/.local/state/blog-publisher`, directory mode 0700. GitHub CLI's dedicated config is below `github/`; files are created with umask 0077. This is outside YogaCloud and source control.
- Service: `blog-publisher.service`, system unit running as jiaqi, enabled at boot and restarted on failure.
- Environment: `/etc/blog-publisher.env`, root-owned mode 0600, containing owner identity/origin/port/state location.
- Check: `ssh yoga-jiaqi "systemctl is-active blog-publisher.service"`.
- Restart only this service: `ssh yoga-jiaqi "sudo -n systemctl restart blog-publisher.service"`.
- Deploy changed application files to the source deployment and restart the service. Do not replace the private state directory. Do not print/copy its credential files.
- Disconnect deliberately through GitHub Settings → Applications → Authorized OAuth Apps → GitHub CLI. This may affect other GitHub CLI installations using the same authorization; do not revoke as routine troubleshooting.

Yoga must be powered and online, and the writing device must be connected to Tailscale. The service and saved GitHub connection survive normal service/computer restarts. GitHub revocation, credential expiry or deletion, network loss, or disk loss can require repair or reauthentication. No perpetual-login or independent disk-backup guarantee is made.

Private drafts now sync through the owner-authenticated `/api/drafts` endpoint to `drafts.json` in the private state directory, outside the repository. Writes check a server revision and are atomic; the preceding state is kept as `drafts.previous.json`. Local autosave remains available offline. Deleted IDs sync too, and simultaneous changes retain the other version inside `savedVersions` rather than creating another sidebar draft. A fresh browser on the owner's Tailscale account restores these drafts. This is a Yoga copy, not an off-server backup.

Private draft attachments live in `STATE/media/<slug>/<filename>` with metadata in `STATE/media.json`, outside source control and YogaCloud. Stage them through the existing owner SSH connection; keep directories mode 0700 and files mode 0600. There is no upload endpoint. The existing owner authentication also protects `/assets/evidence/drafts/<slug>/<filename>` and the merged `/assets/evidence/media.json` manifest. Only PDF, WebP, PNG and JPEG files within the media directory are served; other state files and paths outside that directory are inaccessible.

Private metadata uses the same keyed entries as `_data/evidence.json`, with `pdf` and `previews` paths below `/assets/evidence/drafts/` and an absolute private `download_url`, for example `https://yoga-jiaqi.taile0df21.ts.net:8446/assets/evidence/drafts/ib-physics/paper.pdf`. Private entries are merged only by the authenticated Yoga service; public Pages receives only the committed manifest. Use the private PDF link in the normal draft. Publishing rejects private attachment links before contacting GitHub. To publish later, deliberately copy the attachment to public assets, add public metadata and replace the private link first; this is a separate owner-authorized publication decision. A private attachment is durable Yoga storage, not a public or expiring share link.

The toolbar dot is green only after the current draft collection has been acknowledged by Yoga and GitHub/session plus published index checks succeed. It is amber during sync and red on failure. Clicking it retries sync, without publishing. Sync starts automatically on page open, after edits, on tab/window return, on restored-page navigation and network recovery, and every 30 seconds while visible. Failures retry automatically after 2 seconds, backing off to at most 30 seconds; this also covers failed GitHub/index checks after drafts have uploaded. Offline retries wait for network recovery. Sync requests time out after 45 seconds so a stalled connection cannot leave sync stuck indefinitely. Overlapping index checks share the current request, and another requested sync during an active run is queued. Green describes the last successful check; it cannot predict an outage between checks. Publish remains the explicit action for making writing public, and offers GitHub sign-in if needed.

`Import JSON` also accepts a `blog-draft-update` version 1 file containing `id`, `base`, and `updated` draft snapshots. It checks that the current writing matches the base, preserves routing and identity, retains the prior version, and rejects stale updates. Notes may carry a `reference` ID and `locator`; note citations participate in the same used-source cleanup and same-page numbering as body citations.

Tests: `python -m unittest discover -s scripts -p 'test_*.py'` and `node --test scripts/writer.test.cjs`.

The sidebar shows Drafts, Edits and Published. Published always lists the live posts, including those with an Edits entry. If saved edits exist, selecting Published opens a separate read-only snapshot from the GitHub index; it never replaces the working copy. Edits and Resume edits reopen that working copy. Cached published records remain in the synced collection to preserve identity and conflict checks, but do not appear as drafts. Successful publication clears the Edits entry unless more text was typed while publishing. Discard edits leaves the live post intact. Older unlinked copies are associated with an existing publication by target path or matching type/title, preserving all writing. The publication response updates the current synced record, preserving edits made while the request was in flight.

A complete, verified publication index also refreshes clean cached posts automatically when another device publishes. Genuine unpublished edits retain their content and original revision for conflict checks. If an old edit points to a deleted publication, an exact copy already retained elsewhere is consolidated into saved history; otherwise its writing becomes a recovered draft with the original source metadata preserved in Save JSON. Recovery assigns a new identity and records deletion of the stale one, so old tabs cannot bring it back. Incomplete or failed index requests never authorize cleanup. `node scripts/writer-reconciliation.browser.cjs` covers this behavior on open, reload, focus, and stale-tab recovery.

`node scripts/writer-lifecycle.browser.cjs` exercises the state transitions, reload, sync, discard, in-flight edits and continuous feed navigation against a local fake publisher. It needs Playwright with Microsoft Edge installed; `PLAYWRIGHT_MODULE` can point to an existing Playwright module.

`node scripts/writer-autosync.browser.cjs` checks automatic startup, retries after draft/index/session failures, offline recovery, edits during upload, tab/window/page resume, queued refreshes, request timeouts and restoration in a fresh browser against a local fake publisher. It uses the same Playwright/Edge setup and never publishes a post.

Select a published post in the writing sidebar, then Delete post to remove it from the public blog after confirmation. Matching local draft copies are removed too; Git history preserves the removed version. Deletion checks the original file revision and rejects concurrent changes. The sync status control is a green/amber/red dot with an accessible label; click it to sync again. Both timelines show newest publications first; draft order uses creation dates. Links to the current page (including numbered citations and asterisk explanations) jump within it; links to another page or website open in a new tab. Collapsed post previews expand before jumping to a hidden destination.
